前置：v0.1.1 已完成。只改 `panelagent/importers.py`、`panelagent/repo.py`（如需）、`tests/core/`、`docs/panelagent-core.md`。不碰 backend/frontend/panel_generator.py。不要 git commit。注释英文。

## 真实数据事实（antibody_vault/，已实测）

四个 CSV、四种表头形状，Excel 导出特征：UTF-8 BOM、\r\n、尾随空列（表头末尾多个 `,`）产生空列名、表尾空行；同目录有 macOS 垃圾 `._*` 文件。

- 小鼠 272 行：`Fluorescein,Target,Species,Clone,Catalog Number,Brand,Quantity`；**34 行缺 Target 但有 Fluorescein/Clone/货号**（真实试剂，target 空着）
- 人 204 行：同构；空行较多
- Isotype 44 行：`Fluorescein,Target,Brand,Catalog Number,Quantity`（无 Clone/Species 列）；1 行缺 Fluorescein
- Others 12 行：`Name,Clone,Quantity,Brand,Catalog Number`——**无 Target/Fluorescein 列**（Zombie 染料/Fc block/纯线抗体等），现 schema NOT NULL 全部拒收

当前结果：532 数据行 → 424 导入，108 skipped；其中 Others 全灭、Mouse 缺 target 行被丢。

## 改动

1. **importer 加固**（`panelagent/importers.py`）：
   - 读取用 `utf-8-sig`（BOM）；丢弃全空行与"仅空列名"的尾随列（列名为空字符串/None 的列不进 extra）
   - 跳过条件收紧：**全空行静默跳过（不计 warning）**；`target` 与 `fluorochrome` **都为空**才 skip（计 warning）；仅缺其一的行也导入
2. **schema 放宽**（db.py DDL）：`antibodies.target` 与 `antibodies.fluorochrome` 改为 **NULLABLE**，UNIQUE 约束相应放宽（SQLite UNIQUE 中 NULL 不冲突，天然可用；把唯一键改为 `COALESCE` 表达或放宽为 `(library,target,fluorochrome,clone_name,catalog_number)` 原样——NULL 互不冲突会导致重复导入叠加，改用 upsert 前的 `WHERE` 判重：同 library+catalog_number+clone_name+COALESCE(target,'')+COALESCE(fluorochrome,'') 存在则 UPDATE，否则 INSERT）
3. **Name 列回退**：`Target` 列缺失或空时，用 `Name` 列作为 target；`Fluorescein` 缺失或空时 fluorochrome 存 NULL（不是空串）。Others 的 12 行应全部可导入（target=Name 值，fluorochrome=NULL）
4. **Quantity 等额外列**照旧进 extra JSON（现行为），但空列名的不进
5. **`--inventory-dir` 忽略 `._*` 与隐藏文件**
6. repo.list/search 对 target/fluorochrome NULL 的行正常显示（渲染 `-`）
7. engine（panel generate/diagnose）**不受影响**：候选池本来就按 fluorochrome JOIN channel_mapping，NULL fluorochrome 自然不进候选——不要为此加过滤
