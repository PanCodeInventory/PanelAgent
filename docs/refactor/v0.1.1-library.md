# v0.1.1 — species → library：一个实验室 = 一个 SQLite（多抗体库 + 多仪器）

小迭代，改动面窄。前置：v0.1 已完成。禁止修改 `backend/`、`frontend/`、`panel_generator.py`、现有 `tests/`（除 tests/core）。不要 git commit。代码与注释英文。

## 动机（用户拍板）

一个实验室的抗体资产天然分多个库：Mouse / Human / Isotype / 关联染料 / 刺激试剂……"species" 轴太窄（isotype 不是种属）。目标：**一个 SQLite 文件 = 一个实验室的全部家当**：任意多个抗体库 + 多台仪器（instruments/channels/channel_mapping 已按 instrument_id 隔离，本就多仪器，不用动）。

## 改动清单

1. schema：`antibodies.species` → `antibodies.library`（TEXT NOT NULL，自由命名，无枚举约束）。v0.1 未发布，直接改 DDL，不写迁移。
2. CLI 全线 `--species` → `--library`：
   - `pa init --csv Mouse=a.csv Human=b.csv Isotype=c.csv`（任意库名，可多次）
   - `pa antibody list --library L`、`pa panel generate --library Mouse --markers ...`、`pa panel diagnose --library ...`
   - `--json` 输出字段名同步改 library
3. `--inventory-dir` 启发式扩展：文件名含 `isotype`（不区分大小写）→ Isotype；含 小鼠→Mouse、人→Human 规则不变；都不匹配 → 跳过并 warning。
4. MCP 工具参数 `species` → `library`（search_antibodies / generate_panel / diagnose_panel）。
5. 语义确认：panel generate/diagnose 按单库过滤（isotype 等对照库不进候选池，只能 list/search/annotate）。annotate 的 --library 过滤同样支持。
6. repo/models/importers/engine 相应符号重命名；docs/panelagent-core.md 与 tests/core 同步更新。
