## 已实测的问题（真实 antibody_vault 数据）

`pa panel generate` 候选里 Ly6G/PE-Cy7、NK1.1/PerCP-Cy5.5 亮度显示 `-`。SQL 全量统计：438 支抗体中 23 种荧光名查不到 brightness，覆盖大头：Brilliant Violet 421™(48)、PE/Cyanine7(47)、Brilliant Violet 605™(23)、PerCP/Cyanine5.5(20)、APC/Cyanine7(15)、Alexa Fluor® 647(13)、APC/Fire™ 750(8)、Alexa Fluor® 700(7)、Alexa Fluor® 488(6)、Pacific Blue™(4)、BV510™/650™、KIRAVIA Blue 520™(2)、Super Bright™ 436、Brilliant Violet 785™(14)/786™、Alexa Fluor® 594(1) 等。

根因两个：
1. **同义词断裂**：brightness.json 键用 `PE-Cy7 / PerCP-Cy5.5 / APC-Cy7 / BV421 / BV605 / AF647 / AF700 / AF488 / PB / SB436 / BV786` 缩写；真实抗体与 channel_mapping 用 `PE/Cyanine7 / PerCP/Cyanine5.5 / APC/Cyanine7 / Brilliant Violet 421™ / …` 全称。aliases.json 只覆盖了 10 条 AF/BV 短名，没覆盖 `PE/Cyanine7` 这类 channel_mapping 全称变体。
2. **亮度表键与光谱库键不一致**：brightness.json 有 `Alexa Fluor 647`（无®）等 15 个键不在 spectra 键集合里（spectra 用 `Alexa Fluor® 647`）。

另有 1 支抗体 fluorochrome 为字面 `-`（Excel 占位），应为 NULL。

## 改动

1. **brightness 种子规范化**（推荐做法）：seed 加载时把 brightness 键解析到 spectra 规范名——对每个 brightness 键：若精确等于 spectra 名则直接用；否则走 aliases（alias→canonical）；仍解析不到的键保留原样并收集到 seed warning 列表（`seed.py` 打印一次，方便发现孤儿数据）。规范化后 brightness 以 canonical 名写入表。
2. **补齐同义词别名**（seed/aliases.json）：目标是真实数据 + channel_mapping 的全部拼写都能 resolve 到 spectra canonical。至少覆盖：`PE/Cyanine7`→PE-Cy7 所在 canonical、`PerCP/Cyanine5.5`、`APC/Cyanine7`、`PerCP/Cyanine5.5`、`Brilliant Violet 421™/510™/605™/650™/785™/786™`（若 ™ 形式非 canonical）、`APC/Fire™ 750`、`KIRAVIA Blue 520™`、`Super Bright™ 436`、`Pacific Blue™`、`PE/Dazzle™ 594`、`PE-CF594`、`PE-Cy5.5`、`APC-H7`、`APC-R700`、`BB515`、`V450`、`V500`、`7-AAD`、`AF488/AF647/AF700` 等 channel_mapping 已有键。判断标准：channel_mapping 57 键 + 真实数据出现的全部拼写，逐一对 resolve_fluorochrome 验证。
3. **importer**：fluorochrome/target/clone 的字面 `-` 视为空（存 NULL）。
4. **确实无数据的新染料**（iFluor® 488/555/647、PE/Cyanine8、PerCP/Cyanine5.6 等）：不编造亮度/spectra；aliases.json 加注释段（JSON 不支持注释就放 `"_notes"` 键）记录这些是已知未知。
5. 测试：tests/core 加"真实拼写→亮度"用例（PE/Cyanine7→4 级、PerCP/Cyanine5.5→3 级等，具体值以 brightness.json 现有为准）；加 seed 规范化孤儿键检测用例。
